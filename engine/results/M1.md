# M1: in-guest recursion on OpenVM 2.1 (CPU, build box, 24.11.2026)

Self-recursive SDK (`DeferralAggProver::verify_stark`), VM config rv32im + io + sha2 + secp256k1 modular/ecc +
one verify-stark deferral circuit. Self-test guest (`engine/selftest-guest`), `engine/scripts/m1.sh`:

| step | what | CPU time (16 cores, shared with a build) |
|---|---|---|
| keygen | all proving keys | 27 s |
| build | guest -> exe, baseline | 39 s |
| leaf 7, leaf 35 | plain proofs | 110 s, 134 s |
| node 42 | verifies leaf 7 + leaf 35 in-guest | 301 s |
| node 49 | verifies node 42 (a proof that itself carries deferrals) + leaf 7 | 226 s |
| verify x4 | `hzengine verify`: STARK vs agg.vk + baseline, public values = sha256(journal), image | 0.06 s each |

All four verify. Every child check in-guest: exe commit, vm commit, public values = sha256(child journal).
Image as the guest sees it: exe 29ac9b67…, vm 00e00077… (the deferral output's bytes; the SDK's `app_commit`
prints another encoding of the same commitments).

Not yet: negative tests (a child of another image, a tampered journal) — the host pre-checks refuse them before the
guest runs, so they need a host flag that skips its own checks.
